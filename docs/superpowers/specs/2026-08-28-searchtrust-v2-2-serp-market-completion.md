# SearchTrust v2.2 SERP 市场采集完成记录

日期：2026-08-28

里程碑：V22-022

状态：已完成

设计：`2026-08-28-searchtrust-v2-2-serp-market-design.md`

## 1. 完成范围

V22-022 已交付独立、受预算保护的 v2.2 SERP 市场采集能力：

- 3—5 个已确认原始查询的严格验证与稳定顺序；
- 每份报告一个固定目标点；
- 显式经纬度直用，以及无坐标时的一次免费 Locations API 解析；
- 国家过滤、城市级优先、无 GPS、无结果和位置歧义处理；
- 每个查询一个 Google Maps 和一个普通 Google Search 请求；
- Maps、Local Pack 和 organic 三类结果标准化；
- 每查询每类最多 20 条、只取第一页且不自动改写查询；
- 同一报告统一坐标、设备、语言、国家和 Maps `14z` 视野；
- 每份报告最多 10 个逻辑搜索请求；
- 每个逻辑请求最多 3 次、每份报告最多 30 次实际 provider 尝试；
- v2.1 与 v2.2 共用的 SerpAPI 密钥轮换、冷却、故障分类和脱敏日志组件；
- 位置解析、尝试声明、搜索响应和最终快照的持久检查点；
- 中断恢复、成功调用复用、坏检查点拒绝和跨重启尝试累计；
- 至少三个完整查询组的成功门槛；
- 可供 V22-023 和 V22-031 使用的严格内部 `SerpMarketSnapshot`。

## 2. 运行边界

本里程碑没有新增公开 API，也没有替换生产 `UnavailableV22Executor`。`V22_ANALYZE_ENABLED` 继续默认关闭，完整 v2.2 报告任务不会因本次交付提前开放。

新阶段通过 `CheckpointedSerpMarketStage` 暴露给未来真实执行器。它接收冻结 `AnalyzeRequest`，输出内部市场快照，不生成 Finding、评分、Top Action、竞争对手结论或完整报告。

V22-022 不生成占位或伪造 `evidence_id`，因此也不直接构造冻结报告中要求正式证据 ID 的 `SearchResult`。V22-031 完成证据注册后才能执行最终报告映射。

## 3. 搜索上下文

### 3.1 查询

- 使用 `AnalyzeRequest` 中已经确认的 3—5 个查询；
- 仅清理首尾空白和执行不区分大小写重复校验；
- 不追加城市、服务词或 `near me`；
- 不根据搜索结果改变后续查询；
- 每个查询按 Maps、Google Search 的固定顺序规划；
- 3、4、5 个查询分别恰好规划 6、8、10 个逻辑请求。

### 3.2 设备、语言和国家

- prospect 请求默认使用 `mobile` 和 `en`；
- 存在父报告时使用父报告已冻结的设备和语言；
- 国家来自目标市场 `country_code`；
- Maps 和普通 Google Search 共用同一上下文；
- 上下文任一字段变化都会产生新的规范请求摘要和检查点键。

### 3.3 目标点

- 经纬度成对存在时直接使用，不访问 Locations API；
- 只提供一个坐标时在付费搜索前拒绝；
- 没有坐标时只调用一次免费 Locations API；
- 先按国家过滤，再按邮编、城市、区域、规范名称和地点类型确定性评分；
- 城市级结果优先于同名 DMA；
- 唯一最高结果必须包含合法 GPS；
- 不同坐标的并列最高结果视为歧义，不擅自选择；
- Google Search 使用 `lat`/`lon`，Maps 使用同一中心点和固定 `14z`。

## 4. 结果标准化

### 4.1 类型映射

- Google Maps `local_results` → `maps`；
- Google Search `local_results` → `local_pack`；
- Google Search `organic_results` → `organic`。

每条结果保存稳定记录 ID、调用 ID、查询、类型、原始位置、排名来源、商家名或标题、可用 URL/域名、地点身份字段、地址、电话、分类、评分、评论数、摘要、服务商搜索 ID、响应摘要、采集时间和统一搜索上下文。

### 4.2 排名与重复

- 优先使用服务商合法正整数位置；
- 没有合法位置时使用一开始的原始响应序号，并标记 `response_order`；
- 不因缺少 URL、评分或地址而重新排序；
- 同一商家跨查询、Maps、Local Pack 和 organic 的重复出现全部保留；
- 只有同一调用中身份和位置完全相同的重复记录被跳过；
- 商家身份聚合和出现频率计算留给 V22-023。

### 4.3 响应边界

- 每个响应只保留标准化所需的白名单字段；
- 每类只保留前 20 个原始条目；
- 字符串、分类、数值、JSON 响应和规范检查点都有硬上限；
- 非有限数值、超大整数和超长数字字符串不会进入检查点；
- 不保存原始 HTML、无限制完整 JSON、带密钥 URL 或上游任意错误正文；
- 成功空结果保留为空列表，不误报系统失败。

## 5. 预算与密钥故障切换

### 5.1 逻辑预算

- 每个查询固定两个逻辑调用；
- 报告硬上限固定为 10，不能通过环境变量放大；
- 不使用剩余预算执行分页、额外地点、Geo-grid 或补充查询；
- 读取成功检查点不增加逻辑调用使用量。

### 5.2 实际尝试

- 每个逻辑调用最多三个实际网络尝试；
- 每份报告最坏最多 30 个实际尝试；
- 每次网络调用前先在 Redis 以 `NX` 声明尝试槽；
- 进程在联网后中断时，已声明槽仍计入成本；
- 三个槽耗尽后，在第四次联网前产生稳定的非重试错误；
- 逻辑调用数、provider 尝试数、检查点命中和位置调用数可以确定性映射为任务成本计数。

### 5.3 共享密钥组件

共享 SerpAPI 组件保留：

- 主、次、第三密钥顺序和去重；
- 活动健康密钥优先；
- 认证、权限、月度配额和限流错误后的安全切换；
- 失效密钥冷却；
- 网络、无效 JSON、非密钥 HTTP 错误和密钥池不可用的类型化错误；
- 只记录密钥槽和 SHA-256 安全指纹，不记录密钥正文。

v2.1 `_serpapi_get` 保留原函数签名和公开给现有内部调用者的兼容符号。现有 v2.1 GBP 抓取与 v2.2 GBP 预检回归均通过。

## 6. 检查点和恢复

检查点使用 `serp_market_v1` 版本前缀，覆盖：

- 免费位置解析结果；
- 每个实际 provider 尝试声明；
- 每个成功逻辑搜索响应；
- 最终 `SerpMarketSnapshot` 包装。

检查点键由规范请求摘要生成，包含所有影响结果的搜索参数，但不包含 API key 或原始查询正文。读取时重新验证 schema、请求摘要、引擎、时间、响应白名单、响应大小和 SHA-256 校验摘要。

验证场景中，任务在第四个网络调用后中断：前三个成功搜索在恢复时全部直接命中检查点，第四个请求只补做一次，其余未完成请求正常执行；最终六个逻辑调用对应七次实际尝试。再次读取最终快照时没有产生新网络调用。

坏位置、尝试、搜索或最终快照检查点会产生稳定确定性错误，不进入后续竞争对手阶段。

## 7. 完整性与失败语义

- Maps 和 Google Search 都成功时，该查询才是完整查询组；
- 服务商成功返回空结果仍算成功调用；
- 某一侧失败时保留另一侧已取得的事实；
- 4—5 查询可以有部分失败，但必须至少保留三个完整查询组；
- 少于三个完整查询组时，不生成成功快照；
- 网络、超时、服务商 5xx 和暂时密钥池不可用属于可重试错误；
- 非法参数、位置歧义、坏响应合同、坏检查点和尝试耗尽属于确定性错误；
- 用户可见错误只使用稳定代码和安全文本，不传播内部堆栈或上游正文。

## 8. 配置

新增：

- `SERPAPI_LOCATIONS_URL`；
- `V22_SERP_MARKET_CONNECT_TIMEOUT_SECONDS`；
- `V22_SERP_MARKET_READ_TIMEOUT_SECONDS`；
- `V22_SERP_MARKET_TOTAL_TIMEOUT_SECONDS`；
- `V22_SERP_MARKET_MAX_RESPONSE_BYTES`。

环境配置只能在代码定义的安全范围内调整网络边界。3—5 查询、两个调用、10 个逻辑请求、每调用 3 次尝试、每类 20 条和 Maps `14z` 均为不可放大的代码硬限制。

环境模板继续不包含真实密钥，完整分析开关保持 `false`。

## 9. 冻结合同一致性

本里程碑没有修改冻结的 `AnalyzeRequest`、`TargetMarket`、`SearchResult`、`MarketSnapshot`、共享 JSON Schema 或 TypeScript 类型。

内部快照保留未来证据注册所需的查询、坐标、设备、语言、国家、引擎、时间、服务商搜索 ID、位置和响应摘要。V22-031 将用内部稳定记录 ID 铸造正式证据 ID；缺少正式关联时不得生成最终报告搜索结果。

冻结合同导出检查通过，`contracts` 目录没有产生计划外差异。

## 11. 未执行的真实外部烟测

自动化验证没有调用真实 Locations API，也没有消耗真实 SerpAPI 搜索额度。当前完整生产执行器仍按设计关闭，因此本里程碑只使用脱敏固定响应和本地假服务商验证。

未来真实执行器接入前，应在明确批准的测试账号、查询和预算下执行一次受监控烟测，核对真实地区解析、三类响应字段、空结果、限流和密钥切换。烟测不得单独作为打开完整分析入口的依据。

## 12. 已知后续边界

- 当前只有一个目标点和固定 Maps `14z`，不代表地理网格覆盖；
- 不翻页，因此只表达第一页市场可见性；
- Maps 结果不保证全部位于给定坐标范围，快照只陈述该搜索上下文的实际返回；
- 服务商新增未知区块不会被猜测性映射；
- 竞争对手身份聚合、出现频率、排名相关性和用户确认属于 V22-023；
- 正式 Evidence Ledger 和 `evidence_id` 属于 V22-031；
- 完整报告执行器仍需后续竞品、证据、规则、文案和装配里程碑共同完成。
